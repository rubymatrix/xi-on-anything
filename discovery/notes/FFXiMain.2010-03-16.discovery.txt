Method
------
Ghidra 11.3.2 headless (tools/discover.py), JDK 21. The carried verdicts were each read by
disassembly first. One was wrong and was replaced: the 21-case table of the signed switch mapped
to 0x100065d0, which is code (a window made only of relocated table entries); the real table is
0x10006610. Two 2025-11-12 sites have no counterpart here: the 11-case switch (cmp edx,-5) and the
`mov [edi+0xccc],esi` false start.

The first run's gate failed with 2 conflicts and 3 suspect functions; one --reuse run passed.

What the runtime will meet in a client this old (not verified by running it)
--------------------------------------------------------------------------------
  - The character table is at [chars_ptr]+0x12eb0, not +0x13820 (same 0x8c stride; checked at
    the getter 0x100d2bb0 and the record reader near 0x100d2719). gamecore_presence.c hard-codes
    0x13820, so slot 177 would read the wrong records.
  - FFXiMain calls gamecore slot 441 (+0x6e4, one caller, 0x100d5235), which no later build
    calls and our gamecore does not implement: it would trap. The other 141 slots the 2025-11-12
    build calls are all called here too.
  - No write_line, and chat_add has another arity: addons get no chat text_in.
